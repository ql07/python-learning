## 主案一：d5contacts.json 事故（路径拼接）
- 现象：第一次将json生成地址写死，第二次根目录冒出个没见过的文件
- 原因：1、直接将d4json文件地址写进去，导致写死
-      2、dirname 剥掉文件名时连 \ 一起剥了，+ 一拼 → "d5" 和 "contacts.json" 粘成新文件名d5contacts.json
- 规律：拆出文件夹用os.path.dirname路径拼接用os.path.join，两者配合使用；同一件事只写一处 → DATA_FILE 常量

## 主案二：查"王"却显示最后一个人（循环残影 + 死代码）
- 现象：查询关键字，结果不对/只出一个人（两个含有相同匹配字符的成员之间含有不相干的名字，会导致无法连续保存，print又在循环外面，循环结束返回最后一轮的成员）
- 原因：print 在循环外只拿到最后一轮的 k、v；found = True 紧跟 if found 是死代码
- 规律：循环内拿到的只是"这一轮"，"有没有找到"要转完一圈才知道（found 判断放循环外）
-      所以要将print写入循环内部查到直接输出

## 最爽的一刀：删掉整个分支，功能反而还在
- `'' in k` 恒为 True 的特性 → 空输入天然显示全部
- 你的感悟：理解越深，代码越短
          多考虑类似的问题是bug还是特性，bug注意修正，特性灵活运用，减轻代码

## 重构三刀（一句话各说清干了什么、为什么）
1. DATA_FILE 常量 —— 防改漏（重复需要用到的且语句较长可以防止输错，漏输）
2. confirm() —— 消灭三处重复 y/n，堵静默洞（重复用到的功能可以单独写一个函数，方便调用）
3. add 空名防线 —— 为什么只修 add 不修 modify/delete
-  添加时候，如果将空名加入字典，会导致后续涉及到搜索名字的功能全部出问题
-  而修改和删除的空名不会影响字典成员
